# 本地知识库自动同步到私人 GitHub 指南

> 本文是通用操作说明。示例中的 E:/Notes/Sample-Wiki、ExampleOwner/Private-Wiki、用户名和任务名称均为虚构值。使用前请替换为自己的路径和仓库；不要将访问令牌、密码或真实个人资料写入示例、日志或仓库。

## 用途

这套流程把电脑上的 Markdown 知识库保存到私人 GitHub 仓库，便于版本追踪、备份和使用 GitHub 插件只读查询。用户在本地修改文件后，由电脑上的计划任务定期检查变更、建立 Git 提交并推送到远端；不需要每次手动打开 GitHub Desktop。

## 同步范围与触发条件

- 同步源是本地知识库文件夹中的已跟踪文件。新增、修改和删除会纳入下一次同步。
- 示例计划每 5 分钟检查一次。电脑需要开机、用户已登录且网络可用；离线期间的变化会等到之后的检查。
- Git 会为变更建立本地提交，再推送到私人仓库。成功后可从提交历史查看版本。
- Obsidian 的工作区状态（例如 .obsidian/workspace.json）和易变的图谱界面状态可以加入 .gitignore，避免界面打开、关闭造成无意义提交。实际知识页面仍应正常同步。
- 图片和附件是否同步取决于它们是否位于仓库目录内，以及是否被 .gitignore 排除。

## 前置准备

1. 在 GitHub 创建私人仓库，例如 ExampleOwner/Private-Wiki。
2. 使用 GitHub Desktop 将本地知识库添加为仓库，确认默认分支和远端地址正确。
3. 完成首次发布。远端应选择 Private。
4. 检查 .gitignore，排除缓存、工作区状态、密钥、临时文件和不打算上传的大型文件。
5. 确认本地 Git 凭据可在当前用户登录会话中推送。不要把令牌硬编码在脚本、任务参数或知识库文件中。
6. 私人仓库若处于归档状态会拒绝更新。需要由仓库所有者解除归档后，自动同步才能推送。

## 设置定时同步

推荐把同步脚本放在知识库目录之外，例如 E:/Tools/Sample-Wiki-Sync/sync.ps1。这样脚本和日志不会被当作知识资料再次上传。

脚本每次运行时建议按以下顺序处理：

1. 检查当前仓库路径、分支和远端地址是否符合预期。
2. 若已有暂存内容、合并冲突或远端包含本地没有的提交，则停止并记录原因，不自动覆盖。
3. 从远端获取最新状态，确认本地分支没有落后。
4. 暂存知识库的新增、修改和删除，排除已配置的临时文件。
5. 有变更时创建带时间的本地提交；没有变更时安静结束。
6. 推送到指定远端分支。推送失败时保留本地提交和变更，写入日志供检查。

在 Windows“任务计划程序”中建立任务：

1. 选择当前用户运行，并设置用户登录后可运行。
2. 触发器设为每 5 分钟运行一次，并允许错过后在下次有条件时补运行。
3. 操作指定 PowerShell 程序、脚本路径和脚本所在的“起始位置”。路径含空格时加引号。
4. 先用“仅检查”模式验证脚本可以读取仓库和远端设置；再手动运行一次完整任务，核对任务结果、日志和 GitHub 提交历史。
5. 确认一次按时间触发的任务也成功后，自动同步才算可用。若任务失败，先检查任务历史和脚本日志，不要把“任务已启用”当作“同步成功”。

## 冲突与故障处理

- **远端领先：** 暂停自动推送，检查远端提交，再决定如何合并。不要使用强制推送来消除提示。
- **出现合并冲突：** 保留双方内容，人工解决冲突并验证链接，再重新运行同步。
- **没有上传：** 检查仓库是否已归档、网络是否可用、计划任务是否在当前用户登录会话中运行，以及 GitHub Desktop/Git 凭据是否有效。
- **任务显示成功但文件未更新：** 读取最后运行时间、退出结果和日志，再检查 GitHub 提交历史及目标文件。
- **电脑离线或关机：** 变更先留在本地；恢复联网并登录后，计划任务下次运行再尝试。

## 只读查询与写入边界

GitHub 插件的“读取无需询问、修改前询问”表示修改仍可在获得确认后发生，并不等于撤销写入权限。需要严格禁止 AI 写入时，应使用只读凭据、平台级动作限制或仓库只读设置，并分别验证 ChatGPT 与 Codex 的访问方式。私人仓库的所有者凭据不要提供给查询 Agent。

本地自动同步程序是独立的上传通道；对它的授权不等于授权 ChatGPT 或 Codex 直接修改远端。把这一分工写入项目规则，并定期检查 GitHub 插件权限及仓库访问设置。

## 日常使用

1. 像平常一样在本地知识库中编辑或新增笔记。
2. 等待下一次计划任务运行；通常不超过一个检查周期。
3. 需要确认时，查看同步日志、GitHub 提交历史或文件更新时间。
4. 遇到冲突或认证失败时先暂停自动推送，处理完成后再恢复任务。

---

本指南描述的是一种可复用的工作流程。示例不是可直接运行的部署脚本；真实目录、仓库、分支、忽略规则和安全设置需要由使用者核对。
